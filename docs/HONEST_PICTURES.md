# Keeping generated pictures honest

Written 2026-11-11, in answer to: *"AI can generate multiple unverified images far away from
reality. Please fix those issues."*

Ditto does not generate anything yet. The rules below are the ones its generator must pass
before it is allowed to, and the parts marked **built** already work on any picture, whoever
made it.

## The problem, split into parts

| Problem | What goes wrong | Answer | Status |
|---|---|---|---|
| A generated picture passes for a photo | Shared on, believed, used as evidence | Every output labelled inside the file, in the standard way and signed; optional visible badge | **built** |
| A label is stripped | Screenshot, messenger re-compression, on purpose | Visible badge; and the reader is always told that "no marker" does not mean real | **built** |
| An "edit" of a real photo changes more than asked | A restored or retouched photo with a different face, sign, number or building | Compare with the original outside the area that was meant to change | **built** |
| The assistant treats a generated picture as fact | "Where was I last Sunday?" answered from a made-up picture | Generated pictures are filed in the inference engine's memory as "not a photograph, not evidence" | **built** |
| Many candidates, none checked | The user gets a pile of pictures of uneven quality, some not what was asked | Generate several, score each against the request, show only those that pass, say so when none do | rule written; needs a scoring model |
| Pictures that are dangerous because they look real | Fake documents, receipts, IDs, news scenes, real people | Refused, or made only in a clearly non-photographic style | rule written; needs the generator |
| Details a model invents | Garbled text on signs, wrong numbers, extra fingers | Text is drawn by code, never by the model; detail checks before showing | rule written |

## What is built

### 1. Labels on every generated picture: `ditto label`, read by `ditto verify` and `ditto look`

Two labels go into the PNG file:

- **The industry-standard marker.** An XMP packet with the IPTC digital source type
  `trainedAlgorithmicMedia`, which is how AI-made media is marked for other apps and
  services. Checked with an independent tool: `exiftool` reads it back as
  `Digital Source Type: .../trainedAlgorithmicMedia`.
- **Ditto's signed record.** That it is AI-generated, the prompt, seed, model, source and
  time, a SHA-256 of the pixels, and an Ed25519 signature by the device's key (created on
  first use, readable by the owner only).

Reading a file tells apart:

| Found | Reported |
|---|---|
| Ditto label, signature valid, pixels match | Generated by Ditto from "…"; unchanged since |
| Signature valid, pixels differ | Generated, **then edited** (`verify` fails) |
| Record text changed or wrongly signed | Label tampered with; still treated as generated (`verify` fails) |
| IPTC marker from another generator | Marked by its maker as AI-generated |
| C2PA manifest present | Present, **not verified** here (no C2PA validator yet) |
| Nothing | No marker found, **which does not show the picture is real** |

Optional visible badge (`--badge`): a small "AI" mark in the corner, about 5% of the short
side. It survives screenshots and messengers; the file labels do not.

### 2. Did an edit keep the real picture? `ditto compare ORIGINAL EDITED [--mask MASK]`

For edits of real photos (restore, upscale, remove an object). The mask marks where the
edit was allowed to change things; everything else must still be the original.

| Verdict | Meaning | Thresholds (changed = a channel moved by more than 24 of 255) |
|---|---|---|
| faithful | The real picture is kept | at most 1% of pixels changed and PSNR at least 35 dB |
| drifted | Visible changes outside the area: check them | at most 10% and PSNR at least 25 dB |
| different | No longer the same picture | anything else |

It reports where the unexpected changes are. It works on edits made by any tool, so it can
check a phone's built-in AI editor too. Upscales are compared at the original size; crops
are refused, not guessed.

The thresholds are chosen by reasoning, not tuned on real edits; expect to adjust them on
real before-and-after pairs.

### 3. The inference engine is told

- `ditto look` reports such a picture as **"AI-generated, not a photograph"** and does not
  report photo faults for it.
- In the inference engine's memory it is filed as *"Generated picture, not a photograph,
  not evidence of anything real."* so the language model does not answer questions about
  the user's life from it.
- `photo.compare_edit` is a new tool for the inference engine, next to `photo.inspect` and
  `image.to_svg`.

## Rules for the generator (not built: there is no generator yet)

1. **Label or do not write.** The only way the generator writes a file is through the
   labelling code. There is no option to turn labels off. The badge is on by default for
   anything that looks photographic, and can be turned off only by the user, per picture.
2. **Show only what passed.** Generate several candidates (the night job can afford it),
   score each with a prompt-match model, and show only those above a threshold, with the
   score. If none pass: *"I could not make this well; here is why"*, not the best of a bad set.
3. **Text and numbers are drawn by code.** Captions, prices, dates, names and signs on a
   generated card or poster are laid out by code in the right script (all 22 scheduled
   languages are covered by `ditto scripts`), never invented by the model.
4. **Edits are checked against the original.** Every edit of a real photo passes `compare`
   with the mask the user approved; "drifted" is shown with the changed area outlined;
   "different" is not offered as an edit at all.
5. **Refused, whatever the wording:** realistic documents, IDs, receipts, bills,
   certificates, currency and screenshots of real apps; realistic pictures of real, named
   people; realistic scenes presented as news or events; sexual content involving minors.
   Stylised art (clearly drawn, painted or cartoon) is allowed where the realistic version
   is not, and is still labelled.
6. **Generated is never evidence.** Generated pictures are kept apart from photos, never
   used to answer questions about what happened, and never sent anywhere without the
   approval key (agenticOS's High tier), with the label intact.

## What this does not solve

- A label proves where a picture came from only while it is in the file. Once stripped,
  nothing in the pixels proves a picture was generated. Invisible watermarks in the pixels
  (which survive re-compression) are a possible next step; they are not built, and no
  watermark survives every edit.
- Telling an unlabelled AI picture from a photo by looking at it ("AI detection") is not
  attempted. Current detectors are unreliable, and a wrong "this is real" is worse than
  saying "unknown".
- The signature shows which device labelled a picture, not who owns that device. There is
  no registry of keys.
- C2PA manifests are detected but not validated.
